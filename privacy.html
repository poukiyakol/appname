Data Governance & Privacy Audit

Privacy Policy

Last Updated: October 11, 2026 · Version 2.4 · Compliance: Platform Audit Certified

SECTION 01

Introduction & Privacy Principles

FeedRelay ("we," "our," or "the Platform") provides internal social media publishing and queue automation infrastructure. We recognize the paramount importance of data security and data privacy when interfacing with enterprise social channels.

We operate under a strict Data Minimization and Zero-Commercialization policy: FeedRelay collects only the technical parameters strictly necessary to authenticate with social platform APIs and transmit scheduled short-form video assets. We do not sell data, do not profile consumers, and do not maintain permanent video repositories.

SECTION 02

Data We Collect & Process

FeedRelay processes the following limited categories of data exclusively during authorized publishing operations:

  • Channel Authentication Profiles: Connected channel public usernames, platform account IDs, and avatar thumbnail URLs returned during standard OAuth handshakes, strictly for display in the operator's internal scheduling queue.
  • OAuth Access & Refresh Tokens: Scoped credential tokens granted during official OAuth 2.0 flows, utilized exclusively to authenticate upload requests with destination APIs.
  • Media Upload Assets: Video binaries (.mp4, .mov), captions, titles, hashtags, and scheduling timestamps staged by the operator for automated dispatch.
  • Transmission Diagnostic Metadata: Technical HTTP logs including request timestamps, endpoint status codes, retry counts, and API response IDs to verify delivery status.
What We Never Collect: FeedRelay does not harvest personal contact lists, user comments, direct messages, consumer viewing habits, financial details, or device biometric data.

SECTION 03

OAuth Token Storage & Cryptographic Security

In full compliance with developer platform audit guidelines (including TikTok Developer Security Guidelines, Google API Services User Data Policy, and Meta Platform Policies), FeedRelay enforces rigorous credential protection protocols:

AES-256 Encryption at Rest

All OAuth tokens and refresh keys are encrypted using AES-256 with keys isolated in environment-restricted keyrings.

Ephemeral In-Memory Decryption

Tokens are decrypted into memory only during the active HTTP dispatch window and are immediately unreferenced.

Automated Token Rotation

Background daemons handle refresh cycles seamlessly. Obsolete or expired tokens are immediately sanitized and overwritten.

Zero Frontend Exposure

Tokens are never returned to client-side browser bundles, local storage, or public log streams.

SECTION 04

Data Retention Policies & Ephemeral Buffering

FeedRelay enforces automated, strict expiration intervals for all staged assets and logs:

  • Video Asset Ephemeral Staging (24 to 48 Hours): Queued media binaries are staged in temporary scratch buffers solely to facilitate chunked resumable transfers. Upon receipt of delivery confirmation from the destination social API (or after 48 hours in the event of an unrecoverable failure), the staged video binary is permanently purged from storage.
  • Diagnostic Log Purge (30-Day Limit): API transaction records and error logs are retained for a rolling maximum period of 30 days solely to verify delivery integrity and diagnose potential platform rate-limiting events, after which they are automatically purged.
  • Account De-Provisioning: When an account is disconnected from FeedRelay, all stored channel identifiers and encrypted token entries are wiped immediately.

SECTION 05

Third-Party Platform Disclosures & No-Sale Rule

FeedRelay dispatches scheduled media solely to the official developer APIs of authorized third-party platforms selected by the operator:

  • TikTok: Transmissions via TikTok Commercial Content API and TikTok for Developers.
  • YouTube: Transmissions via YouTube Data API v3 and Google Cloud Services.
  • Meta / Instagram: Transmissions via Instagram Graph API and Meta Content Publishing APIs.
Absolute Prohibition on Commercial Sale & AI Ingestion: Under no circumstances does FeedRelay sell, lease, exchange, or transfer user account information or video content to third-party data brokers, ad networks, or commercial analytics firms. We do not use customer videos, metadata, or creative assets to train artificial intelligence or machine learning models.

SECTION 06

Data Subject Rights & Revocation Mechanisms

Operators retain complete sovereignty over their connected profiles and authorization credentials:

  • One-Click In-App Revocation: You can disconnect any social account at any time in the FeedRelay management view, triggering instantaneous deletion of all encrypted tokens.
  • Direct Platform Permission Revocation: You can revoke FeedRelay's access directly at the platform level at any moment:
    • TikTok: Settings > Security > Manage App Permissions
    • Google / YouTube: Google Account Security > Third-party apps with account access
    • Meta / Instagram: Settings > Security > Apps and Websites
  • Data Erasure Requests: To request an expedited manual purge of historical dispatch logs, operators may contact the Data Governance team.

SECTION 07

Security Safeguards

We implement industry-grade technical and organizational safeguards:

  • Transport Encryption: All communications between clients, FeedRelay, and external social media APIs require TLS 1.3 encryption.
  • Role-Based Access Control: Strict least-privilege access rules ensure only designated automation daemons can read temporary token vaults.
  • Vulnerability Management: Continuous automated package auditing to eliminate CVE vulnerabilities across dependencies.
